## 최종 검증과 적용 경계

새 checkpoint schema v2는 예약 파일과 mutable checkpoint의 예약 목록·열 소유 범위를 대조한다. 독립 검사 HVP도 생성 예약의 해시에 연결하며, 완료 검증만 수행한 재개 예약으로 비용을 잘못 돌리지 않는다. 예약/열 삭제·잘림·orphan·잘못된 소유·한쪽 hash 손상은 HVP와 데이터 쓰기 전에 거부한다. active 수치/receipt/programming 거부는 종료 상태이며, 예산 대기만 재개한다. 잘못된 query는 기존 완료/부분 cache를 바꾸지 않는다.

새 coordinator는 앞으로 사용할 모듈이다. guard가 반환한 실행·수치·자원 상태와 관련 파일 hash를 먼저 ledger에 저장한다. 완료한 parent가 child JSON을 읽을 수 없거나 내용·hash가 맞지 않으면 failed로 낮춰 종료하며, 이미 실패한 parent의 잘못된 child를 다시 파싱하지 않는다. 기존 역사적 script와 실제2회 기록은 변경하지 않는다.

집중 시험69 passed, 기존 경고18개, 오류 수준 basedpyright0. kernel21건·새 coordinator5건·기존 endpoint 연결43건을 한 실행에서 검사했으며 과거60개나 독립 점검과 합산하지 않았다. 검증은 합성/파일/mocked guard 기반이고 이번에는 실제 FV/HVP/PCG/최적화/재분석/전체 CI를 실행하지 않았다. Graphify는 캐시 구조를 참조한 뒤 네 파일만 격리 갱신했다(87 nodes/289 edges); 공유 graph/report는 불변이다.

v1 실제 checkpoint에서 canonical status=completed와 last_status=audit_validation_pending의 차이는 이전 거부 상태를 남긴 metadata 표현 문제였다. v2는 새 저장/완료 상태를 일관되게 기록하지만, 과거 JSON을 덮어쓰지 않는다. 당시 실행된 v1 코드/원본은 Git과 이전 manifest로 유지한다. 신규코드 source SHA가 과거 manifest와 다른 것은 의도한 수정이며 과거 숫자를 재인증한 것이 아니다.

추가 과학 검토의 핵심도 보존한다. A=Hff와 D=Hdd는 각각SPD이며, 저장 행렬의 결합 정규화 특잇값 최대는1.54856745>1이다. Schur 음의 방향에서 초기장+120.8423352, 교차항-241.6846704, 동역학+93.3410147의 합이-27.5013205다. 이는 보관 행렬만의 재계산이고 새 FV 스텝이 아니다. 다음 원래J 탐색은 교차항과 비영gf 보정항을 유지하고 shift의 SPD 여부·조건수·스텝 norm·실제J·분기를 함께 평가해야 한다. Schur floor1은 전체 수정행렬 floor1 또는 full-step 안전성을 뜻하지 않는다.

앞으로는 이번에 재현한 저장 계약만 닫고 현재점의 결합된 방향과 스텝 크기 제어를 별도 과제로 진행한다. 새 solver/기상모형/물리적 성능 주장을 이번 audit에 추가하지 않는다. 아직3시간 적격 정상점·수반·재분석은 미완료다.
