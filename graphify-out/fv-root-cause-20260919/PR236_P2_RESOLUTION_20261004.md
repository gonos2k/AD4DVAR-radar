수학적 원인: J(t,η;p)=t²/2+|η|+pη는 같은 c=(0,0)에서도 법선 기울기가 p에 따라 바뀐다. p=0의 부호(-1,+1)를 p=2의(+1,+3)에 붙일 수 없다. 기준 p 연결은 수치 재검증과 별도의 증거 계약이다.

수치해석: 반례→좁은 수정→실제 보관자료의 다른 root 성공/변조 거부 시험. dtype·정상성·수반 허용오차와 원시 수치를 바꾸지 않는다. 전면 CI나 긴 FV 실행은 하지 않는다.

기상학: 관측·배경 파라미터 p가 달라지면 같은 제어라도 다른 동화 문제다. 출력은 조건부/전체 응답, 실행·수치·물리 검증 상태를 계속 구분한다.

Graphify: 기존 격리 AST를 참조하며 변경 네 파일만 별도 임시 복사본에서 추출한다. 공유 graph/report에는 쓰지 않는다. 이전 보고서 원문 복구 공백은 PR236 기록대로 유지한다.

## 검증과 종료 판단

- P2-1: 기존 함수에서 같은 c에 다른 p의 법선·수행 검증이 허용됨을 재현했다. 측정 법선 top/ref와 수행 검증의 기준 p를 필수화하고 응답 입력의 SHA와 비교한다. 미실행 기록은 p를 생략할 수 있지만 제공한 p는 일치해야 한다. 누락/불일치와 passed/failed/inconclusive 검증, 기존 AD·prior·pivot 시험을 함께 유지했다.
- P2-2: `_stationarity_gate`가 caller root를 직접 받는다. 다른 root B의 정상 세 보관자료를 끝까지 변환하고, importer root A를 빈 곳으로 바꿔도 성공한다. A가 정상 자료를 보유해도 B 소스가 바뀌면 거부한다. `_ROOT`는 기본 인자 외 파일 접근에 사용하지 않는다.
- `PR236_P2_TESTS_20261004.log`: 44 passed, 기존 경고18. 새 집중 묶음이며 이전 28/113 시험과 누적하지 않는다.
- `PR236_P2_TYPES_20261004.log`: 네 변경 소스/시험의 오프라인 오류 수준 타입검사 오류0. 모든 경고 범주의 부재를 인증하는 것은 아니다.
- `response_contract_p2_20261004/render_result.json`: 새 코드 해시로 별도 변환 출력 생성. 세 원시 SHA 전후 일치, measured normal top/ref와 검증의 기준 p 일치. 이전 `response_contract_20261004` 출력은 당시 코드의 역사적 자료로 그대로 보존한다.
- `PR236_P2_GRAPHIFY_20261004.json`: 변경 네 파일만 격리 AST 추출. 공유 graph 및 보고서 복구 안내 파일의 바이트는 이번 수정 전후 동일하다.

두 P2의 좁은 계약·경로 결함은 종료한다. 이는 기존 세 수치 결과의 추가 FV 인증 또는 3시간 수렴 진전이 아니다. 3시간 정상점·응답, 자동 활성면 선택, 독립 기상 검증은 계속 미완료다.
