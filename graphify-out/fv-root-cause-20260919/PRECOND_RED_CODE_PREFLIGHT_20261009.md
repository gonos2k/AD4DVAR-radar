## Findings

The intended numerical path is mathematically coherent under its stated restrictions. At the same saved `33cb86ca…` point the factory requires the 26-control/13-parameter fixed case, 3×4 all-detected observations, no neural prior, zero field-smoothness weight, and exact identity control-prior residual. `problem.observation_residual` returns the quality-standardized, correlation-whitened rows used by `problem.objective`. The scalar pseudo-Huber factor `(delta/hypot(delta,r))**3` is `rho''`, not the existing IRLS weight. The implementation builds each side's rows with one `torch.func.vjp` forward and 12 scalar cotangent pullbacks; the two sides therefore account for 24 row VJPs, distinct from four current direction HVPs.

The diagonal projection formulas are correct: `projector.square() @ prior` computes `diag(P diag(prior) P)`, and the same contraction computes the face-curvature diagonal for diagonal `Q_cc`. The fixed floor `max(1,B_raw)` makes each inverse weight positive and no larger than one. `-P W P g_mix` is tangent and has negative mixture slope for nonzero tangent gradient. The core checks the actual common-face jump and both side slopes, validates a supplied override against both the current normal and retained-coordinate chart, and records a per-HVP direction hash. The new runner executes both model arms before selecting by the predeclared actual-F²/J/baseline tie order; only the selected arm receives final closure and commit. An incomplete second-arm HVP raises before commit, covered by a synthetic interruption test.

**P2, future callback-contract gap (not a defect in the current two-arm factory):** `bounded_continuation` computes HVPs along each spec's `direction` (`fv_point_3h_tangent_continuation.py:388-400`). If a spec omits `direction_override`, `tangent_model` independently recomputes the baseline direction; the core does not assert that it equals the HVP direction before candidate evaluation. The current adapter is consistent: its baseline spec comes from the same deterministic `tangent_direction` call and checks equality with `-P g_mix`; its robust-GN spec passes the same vector as both `direction` and `direction_override`. The generic helper could accept a future mismatched spec, form `DF` from HVPs for one vector, and search a different vector. The parent receipt later compares the HVP direction hash to the stored arm direction and would reject the run, but that is after child candidate work. Before widening this API, require each spec's direction to match the model direction before search, or require explicit validated overrides for all specs; add a synthetic mismatch regression.

**P2, projected-row tolerance may falsely refuse near-normal rows:** the current row-parity check budgets `||P A_- - P A_+||` using only `max(||P A_-||,||P A_+||)` (`fv_point_3h_tangent_precondition_comparison.py:414-422`). Projection cancellation error scales with the unprojected rows as well. If a row has a large normal component and a very small tangent component, two mathematically common-face rows differing only by a normal multiple can project to values whose roundoff difference is `O(eps*||A||)` while the current allowance is `O(eps*||P A||)`, causing a conservative refusal. This cannot admit a bad row; it can stop a valid comparison. A scale budget should include the unprojected row norms (with `||P||=1`) as the arithmetic scale, while retaining the common-face row check.

**P3, targeted regression gaps:** tests cover the identity metric reproducing baseline, dense-vs-diagonal algebra, row-cost reconstruction/whitening/masks, a strict better-F² winner, the paired-arm interruption, and synthetic child budgets. The identity test verifies `W=I`; it makes no general scalar-rescaling invariance claim, and the RED design memo explicitly rejects such a claim. The current synthetic set does not directly exercise projected-row-parity refusal, a mismatch between a direction spec and its HVP vector, or the F²-tie → J-tie → baseline selector cascade. These are the most valuable pre-launch additions if the source is still being edited.

**Comparison semantics to keep explicit:** the shared line-search helper stops each arm at its first passing alpha, or exhausts its cap if none passes; it does not evaluate all 16 slots after an earlier pass. Both arms nevertheless finish their own standard first-pass-or-exhaustion search before winner selection. If “fully attempted 16 slots” is intended to mean exhaustive evaluation of all 16 candidates even after acceptance, the current helper does not implement that policy. The written GREEN design says “no more than 16 candidates per arm” and supports the first-passing-alpha interpretation, so clarify before freeze rather than silently changing the search semantics.

## Mathematical scope and limits

The `-mu P Q_cc P` term uses `mu=n·g_mix/n²` with `L=J-mu Q`; its sign and tanh second derivative are correct. The metric includes only the positive robust-GN row term, original-prior projection, and this diagonal constraint correction. It omits `sum_i rho'(r_i) Hess(r_i)` and other full-Hessian structure. The current tangent residual is nonzero (`||g_T||≈0.07173`), so `mu` is a normal projection scalar rather than a stationary KKT multiplier. The resulting `B` is a floored SPD search metric, not the exact restricted Hessian, not a Riemannian-curvature certificate, and not evidence of a minimum. Side/mixture dependence of this approximate diagonal is possible; exact extension cancellation is not claimed.

The final-HVP comparison must use four fresh products at the same base: two sides for `-P g_mix` and two sides for `-P W P g_mix`. No HVP at `a579d422…` is current at `33cb86ca…`. Preserve the existing 0.05 chart radius, per-arm maximum of 16 first-pass backtracking slots, theta bounds, actual native-J/F² Armijo, current paired-branch/face checks, side-gradient closure, and one-commit behavior. Selection uses actual accepted endpoint F², then native J within the frozen tie tolerance, then baseline as the deterministic tie-break; a model prediction is not a new acceptance gate.
