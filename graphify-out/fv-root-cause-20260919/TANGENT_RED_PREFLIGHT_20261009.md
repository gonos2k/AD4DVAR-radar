## Actionable findings

1. **Armijo evaluator does not receive the trial alpha.** `search_candidates` owns the dyadic `alpha` and computes `theta`, then calls `candidate_eval(candidate, theta)` (`fv_point_3h_tangent_continuation.py:186-206`). The required facts include `J_armijo_passed` and `F_squared_armijo_passed`, whose thresholds depend on the trial step (`J(x+αd) ≤ J(x)+cα∇J·d`, and the analogous residual merit rule). For a general supplied `chart_candidate`, the callback is not given `alpha`, the base point, or the model slopes, and cannot reliably reconstruct the same Armijo threshold from the candidate alone. Pass the trial alpha and the base/model quantities needed to evaluate each threshold, or move the Armijo comparisons into this kernel. Current tests return unconditional gate booleans and do not exercise the threshold contract (`tests/test_fv_point_3h_tangent_continuation.py:94-107`).

2. **Exceptions discard the last accepted state from the API result.** The loop updates `control` and `current_theta` only after final closure (`:281-286`), so normal refusals return the previous confirmed state. But exceptions from `current_products`, either HVP callback, candidate evaluation, or `final_repeat` propagate (`:257-276`) before the only result containing that local state is returned (`:287-290`). A later callback failure after one or more valid commits therefore leaves callers without the last confirmed point/records, contrary to the transactional continuation docstring’s promise that the last confirmed control and theta survive refusal (`:244-250`). Convert callback failures into a terminal record that returns the committed state, or provide an explicit durable commit/progress channel before invoking the next callback.
