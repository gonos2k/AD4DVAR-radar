# R2 active-face preflight and numerical refusal boundary

Archive/plan/source/runtime/input checks, binding construction and conversion of
the original saved vector into a representable face coordinate are preflight.
Failure there propagates; no numerical correction or qualified result exists.
The parent must classify a nonzero exit with no worker JSON as execution failed,
numerical status not reached. It must retain the raw log/resource record and must
not publish a sensitivity. This does not prove that the physical problem lacks a
solution. In the declared captured vector the original pivot contribution is
well resolved; the preflight classification is not a tolerance relaxation.

After a tangent coordinate exists, the initial selected-face trace and all
Newton candidates are numerical qualification. Known chart-lift, limiter and
other-face margin refusals produce a terminal branch/curvature or numerical
refusal record. Structural-zero, stage-count/replay and fixed-parameter mutation
failures are invariants/programming errors and propagate. The mocked regression
checks that an initial numerical refusal does not call the optimizer.

Only the parent may assign execution completion after exit 0, no resource or
monitor failure, finished phase and actual before/after source/input checks.
Worker numerical stationarity remains separate from execution completion and
from normal, response and physical validation.
