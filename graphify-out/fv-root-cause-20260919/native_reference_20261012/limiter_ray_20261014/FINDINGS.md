# 현재 native 후보의 실제 minmod 전환 진단 — 2026-10-14

현재점 `6ca56498…`에서 저장된 결합 방향을 더 작은 배율로 실제 평가했다. **기준점의 AD 내적은 저장된 하강 예측과 일치하고, 조금 더 큰 이동에서 실제 minmod 선택 전환과 기울기 반전이 확인됐다.** 이번 실행은 진단이며 후보를 채택하거나 최소점을 인증하지 않았다.

원래 26제어 native J, 고정 관측·prior, 기존 두 유동면의 24D 차트를 사용했다. 이전점의 PD Hessian은 저장된 방향을 재구성하는 행렬로만 사용했다. 현재점 곡률로 간주하지 않았다. 세 공통 배율의 제어 해시와 비용은 이전 coupled-ray 기록과 bitwise 동일하다. 미래점수는 계산하지 않았다.

## 선택 전환의 위치

minmod는 같은 부호인 두 slope 중 절댓값이 작은 것을 선택한다. 2⁻¹⁰에서 **x 셀 (1,1), stage 47·48**이 left→right로 바뀐다. stage 47의 원래 피연산자는 `[0.40972757928, 0.40973628294]`이고 이동 후 `[0.40973515041, 0.40973009656]`이다. 단계 번호는 0부터, 공간 셀 번호는 실제 배열의 interior index다. 처음 확인된 전환은 샘플 배율 2⁻¹²와 2⁻¹⁰ 사이이며 정확 사건 위치나 순서는 계산하지 않았다.

2⁻⁷에서는 **y 셀 (2,3), stage 123·124**의 right operand가 양수에서 음수로 바뀌어 right→inactive zero가 추가된다. 네 변경 모두 원래 `_minmod`의 엄격한 부호·대소 비교로 독립 검산했다. 기존 tolerance-based qualification audit는 변경하지 않았다.

2⁻²⁰·2⁻¹⁶에서는 minmod 변경이 없는데도 `qy[2,1]`의 exact sign이 0→+1로 바뀐다. 2⁻¹⁰에는 `qy[4,3]`에서 0→−1 변화가 있다. 이들은 차트가 제한하는 두 유동면의 부호 변화이며 roundoff와 일관된다. 이 trace에는 flux 크기를 기록하지 않아 residual 상한이나 roundoff 인과를 인증하지 않는다. 별도의 flux-sign 기록으로 보존했다. **limiter 선택과 유동 부호를 함께 넣은 이전 전체 서명만으로 모든 비영 이동의 limiter 전환을 주장할 수 없다.** 이전 raw 자료를 덮어쓰지 않고 이 진단에서 범위를 바로잡는다.

## 자원·검증·남은 범위

- direct native J 6회와 chart gradient 6회, Hessian·HVP·미래점수·채택점은 0회다. 기존 raw stage trace가 없던 세 공통 배율은 trace와 비용 closure를 위해 재평가했다.
- 추적된 이후 direct-J 누계는 506→512로 한도에 도달했다. 원래 reference 2000회를 포함한 추적 누계는 2512이며 모든 과거 중단·debug 호출의 총계가 아니다.
- gradient는 새로운 진단 PLAN에서 추가 6회를 선언해 128→134회가 됐다. **이전 chord PLAN의 누계 gradient cap 128 준수는 주장할 수 없다.** 이전 gradient cap을 그대로 유지하는 사전검사가 없었던 한계를 ACCOUNTING에 명시했다. 이 phase에서 추가 계산하지 않는다.
- 준비를 포함한 실행시간 13.7856초, peak RSS 336,527,360 bytes다. 이전 추정 장부와 합친 비용은 3437.7707초이며 전체 세션 wall 인증이 아니다. 60초 정책은 호출 사이의 검사이고 실제 기록은 범위 안이었다.

후속 계산은 사건을 포함한 원래 최적조건의 계획이 필요하다. 사건 이전 이동과 활성 조건을 분리하고, 47·48 단계 조건의 독립성을 확인해야 한다. 현재 direct-J 예산을 리셋해 동일 chord를 반복하지 않는다.
