# GREEN design review: bounded repeated dual-merit correction

## Finding

The smallest sound design is a bounded outer loop around the existing live-HVP Newton solve and dual-merit candidate search. Start from the accepted `e0b04a…` control in `a35_dual_merit_20261006_attempt1/step.json`; preserve the original objective, priors, observations, fixed parameters, and endpoint branch gate. At each accepted control, recompute the current objective and full gradient, create an HVP operator at that control, solve for a new direction, then run the existing dual-merit search along that direction. Reuse direction and `Hs` only within that iteration's backtracking grid.

The f82c Hessian may be factored once as a fixed SPD preconditioner. It must never be substituted for the live current-point Hessian, described as current-point curvature, or used to claim current/global SPD. No automatically shifted/J-only fallback is justified by this design.

## Mathematical conditions

For `g = grad J(c)`, `H = J_cc(c)`, and an inexact Newton solve `H s + g = r`, the two directional slopes are `gᵀs` and `gᵀHs = -||g||₂² + gᵀr`. Require both to be finite and strictly negative before entering candidate search. The `1e-10` true relative linear residual supports negative `gᵀHs` through Cauchy–Schwarz, but it does not by itself ensure `gᵀs < 0` unless the live operator is positive definite; retain an explicit descent gate for each slope. PCG's observed positive Krylov products are not a full-Hessian SPD proof.

For each candidate use actual values and both existing Armijo gates: `J(c+αs) ≤ J(c)+1e-4 α gᵀs` and `Φ(c+αs) ≤ Φ(c)+1e-4 α gᵀHs`, where `Φ=||grad J||₂²/2`. Also require that candidate's complete strict 3,600-stage endpoint branch/margin checks pass. The trial grid is `α_k = min(1, 0.05/||s||₂) 2^-k`, `k=0…15`; the 0.05 bound applies independently to each iteration and is not a persistent radius reduction.

Within a common differentiable branch, negative slopes imply a sufficiently small step can satisfy both Armijo inequalities. They do not guarantee success on the fixed 16-point grid, across limiter/branch changes, or within the resource limit. `Φ` decrease is a merit decrease, not a minimum certificate: `Φ=0` also at stationary saddles, and `Hᵀg=0` can occur for nonzero `g` when `H` is singular.

## Minimal reusable API and state flow

1. Keep `dual_merit_search(...)` as the per-iteration line search. It already records candidate values, actual `J`/`Φ`, strict endpoint branch and margins, and rejection reasons. Invoke it only after current-point direction checks. Its inputs must come from the current iteration, never the old a35 direction or its `Hs`.
2. Preserve the existing hard-coded `solve_newton_direction` wrapper and its pinned source unchanged. In the new caller, make a thin direct call to `advar.matrix_free.pcg` with the current live-HVP operator, the `-g` right-hand side, the existing f82c preconditioner, `rtol=1e-10`, and `max_iterations=40`. Retain caller-level gates for convergence, finite direction/residual, true residual at `rtol=1e-10`, and both dual slopes. Do not edit the historical wrapper merely to parameterize its `104`-iteration default.
3. Share one HVP counter across the outer run (cap 90 total), while rebinding the live operator to each current accepted control. Count every started product, including PCG operator products, any restart products, and each post-solve true-residual product; check the cap before product 91 and report started/completed counts separately. The repeated caller can own this thin counter without changing the historical live-HVP source.
4. Treat each accepted candidate as provisional until branch-signature recapture, fixed-input/source integrity, and post-candidate diagnostics complete. On closure failure, mark `candidate_not_committed`, retain the last fully committed control, and preserve all completed iteration receipts. A later iteration may start only from a committed accepted endpoint and must recompute `J/g/Φ` there before constructing a fresh HVP.
5. Write iteration-indexed records with base control/hash, fresh `J/g/Φ`, live direction and solve residual, HVP/PCG counts, both slopes, all trials, commit result, endpoint hash, and stop reason. Do not silently rewrite earlier records or present a partially accepted run as complete.

## Frozen run bounds and statuses

Pin one guarded launch with at most 3 outer iterations, 90 total live HVP calls, 40 PCG iterations per solve, at most 16 dyadic candidates per iteration, radius 0.05, true residual `rtol=1e-10`, 720 seconds internal, 780 seconds outer, and sampled peak child RSS at most 1 GiB. The 90 HVP budget includes each solve's true-residual verification and any restart/operator calls, so it may stop the run before a third solve or before all three iterations complete. These are upper bounds, not a promise of three completed solves. The 780-second outer bound leaves 60 seconds for process supervision/receipt closure after the internal deadline. A budget refusal ends this sole launch; do not retry with wider limits. Record the realized count separately from each cap. At most 48 candidates is a search-grid upper bound, not a promise that the time budget can evaluate all of them.

Stop on any of: the `||g||∞ ≤ 1e-10` numerical root gate; 3 committed steps; HVP/PCG/time/RSS limit; no dual-descent direction; PCG or curvature refusal; or exhausted candidate grid. Preserve distinct statuses for stationarity-gate reached, iteration limit, budget refusal, curvature/linear-solve refusal, branch refusal, and `dual_merit_grid_exhausted`. Do not label a bounded-grid miss as proof that no root exists.

If `||g||∞ ≤ 1e-10` is reached, report `root_pending_audit`: this means only that the configured numerical stationarity gate passed. The repeated correction must not emit `finaleligible`. That label is reserved for a later independent qualification that includes the required current-point curvature and branch eligibility, original-Hessian adjoint/response and reanalysis gates, and any issuance-specific checks. A converged gradient alone proves neither a local minimum nor a physically valid/forecast-improving result. Keep score, response/adjoint, reanalysis, physical validation, and forecast evaluation explicitly `not_performed` here.

The integration manifest should pin the repeated runner, modified solver and existing search/kernel dependencies, focused tests, immutable accepted-point receipts, fixed policy, and one fresh output directory. Close locally with focused regression tests for fresh HVP rebinding after acceptance, same-iteration reuse during backtracking, cumulative HVP cap (including true-residual calls), per-solve PCG cap, strict endpoint branch rejection, provisional-acceptance rollback, preservation of committed iterations on later refusal, and root-pending versus final-eligibility labels. Run type checks and a code-only incremental Graphify refresh in an isolated output location if code changes; do not overwrite the baseline graph or rerun full semantic extraction. Then require independent GREEN and RED review of the implementation and receipts before treating the run as complete. The actual repeated FV launch is a single separately pinned run; this design review performs no new FV, HVP, PCG, forecast, adjoint, or reanalysis computation.
