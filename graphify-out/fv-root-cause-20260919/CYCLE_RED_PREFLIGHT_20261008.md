Scope: read-only design audit of the new one-exploration / bounded-correction cycle and its receipt, termination, and CLI paths. I did not run FV, AD, HVP, PCG, or the test suite. No material blocking counterexample was found in the reviewed paths.

## Findings

- **PR262 and PR260 provenance is closed for this mode.** The new plan is fixed to the PR262 accepted-control hash `26e830dc…` and separately identifies PR260 `2cdccade…` as the pre-exploration comparator. The loader verifies the sample child/run/resource digests, committed trial/control and metrics, source/input/runtime closure, and the parent-to-child hash relation. It also verifies PR260's saved source receipt and endpoint closure. The old live PR260 plan is preserved through the archived source manifest rather than accepted with changed live source bytes. See `fv_point_3h_exploration_correction_cycle.py:65-128,131-227` and the immutable plan.
- **The initial cycle state is freshly checked before correction.** The continuation reconstructs the exact PR262 control, checks its input/runtime identity, and freshly measures J, Φ, gradient, and strict endpoint branch before starting. The old sampled direction is not reused. Each correction then uses the current full gradient and a fresh current-point HVP. See `fv_point_3h_model_guided_continuation.py:465-528,553-582`.
- **The recovery gate is a net endpoint comparison, not a root test.** It compares final J and Φ against the PR260 values with a scale-aware FP64 roundoff margin. A recovered status requires both values to be below that historical reference; “root pending audit” is checked first and remains distinct. The cycle is capped at one exploration, three correction steps/HVPs, 16 candidates per step, one guarded launch, and the declared time/RSS limits. See `fv_point_3h_exploration_correction_cycle.py:52-58,230-254` and `fv_point_3h_model_guided_continuation.py:529-537,697-723`.
- **Commit failure preserves the previous committed endpoint.** A correction is provisionally measured and freshly rechecked before source/input/runtime closure; `_commit_iteration` runs only after those checks. A failure marks the active trial uncommitted, keeps the prior committed state/count, and is surfaced as refusal or execution failure. See `fv_point_3h_model_guided_continuation.py:648-695,727-762`.
- **The child CLI wiring is consistent.** The cycle entry point requires plan SHA, output, resource, and log paths; it delegates the guarded launch to `guided.run`. That runner invokes the guided child with the cycle plan, plan SHA, and output, while resource/log paths remain outer-runner receipts. The child parser accepts those arguments and dispatches the cycle plan through its explicit loader branch. See `fv_point_3h_exploration_correction_cycle.py:257-273` and `fv_point_3h_model_guided_continuation.py:139-145,765-835`.
- **The dispatch helper avoids a static reverse import.** The cycle module loads the shared runner through `_guided() -> ModuleType` using `importlib`; the guided module imports the cycle adapter locally only for cycle-specific plan/base/assessment handling. This keeps module initialization one-way and avoids mutating module globals. See `fv_point_3h_exploration_correction_cycle.py:57-64,263-264`.

## Limits retained

Each candidate has an independently measured strict endpoint, but a change in branch signature remains a recorded transition and does not establish a single smooth branch along the path. The recovered status establishes only the bounded J/Φ endpoint comparison; it does not certify stationarity, a root, forecast skill, or physical response. No final tolerance or objective change is introduced.

The outer parent receipt validates generic child completion, source/input/runtime closure, iteration count, and final committed control. It does not independently recompute the child's cycle-reference assessment or prove that `cycle_recovered` agrees with those fields (`fv_point_3h_model_guided_continuation.py:790-808`). This is a retained nonblocking boundary: the child computes the recovery assessment from its fresh committed state, but any actual run still needs a raw post-run audit that checks cycle metadata against the final J/Φ and pinned PR260 reference.
