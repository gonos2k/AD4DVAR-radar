# 결합 GN 재개의 한 스텝 확정과 RSS 중단

PR #273 확정점 `4035904e46c11c67a6f937039fe3c88b0516330b05f3ba9d57c4cfa619423ab7`에서 같은 후보별 최소 θ·결합 robust-GN 정책을 최대 세 채택까지 이어가도록 구현했다. 실제로 첫 스텝을 확정했지만, 두 번째 계산점의 row VJP 중 RSS 한도를 넘어 guard가 중단했다. **세 반복 완료가 아니다.** 한도를 올리거나 같은 계획을 다시 실행하지 않았다.

## 구현과 사전 검증

원래 J·관측·prior·경계·시간·26제어·영 유량 차트와 GN/최소 θ 수학을 유지했다. 현재점마다 기존 coupled factory에서 GN spec만 골라 사용한다. baseline 방향의 대수 계산은 factory의 일부지만 baseline HVP나 후보 평가는 하지 않는다. 각 계산점에서 새 양측 row24회·12차원 풀이1회·양측 HVP2회를 사용하며 과거 행렬/미분을 새점에 승계하지 않는다.

재개 로더는 PR #273의 무손실 원시자료·계획·source/input/runtime·선택 GN·개별 gradient 최종 승인을 확인한다. 전체 이전 원시자료를 검증한 뒤 입력/runtime 기준과 선택점 closure만 메모리에 남긴다. 보관 자료를 삭제하거나 한도를 느슨하게 바꾼 것은 아니다.

shared parent는 GN 모델명을 포함한 제어·θ·현재 HVP 계보와 각 계산점의24개(side,row) Cartesian 기록·12차원 풀이를 연결한다. 완전 row batch 뒤 양측 parity에서 거부되는 경우는 스텝 없는 종료 거부로 구분한다. 풀이를 완료했지만 완전한 방향/풀이 근거를 얻지 못하면 child closure failure로 분류하며 이전 확정점을 보존한다. 합성 회귀는3확정72row6HVP3풀이, 다음점 거부, row-only 거부, 최종 승인 실패, 풀이 근거 누락을 다룬다. 생산용 미분 독립 검증이 아니다.

기존 최소 θ·접선 방향·배율·검색·최종 승인·bounded 반복의 여섯 함수 AST는 그대로다. 영향 시험88개 통과·기존 경고18개·42.19초, 타입 오류0이다. source139개/archive148개를 계획 SHA `1f0eff706a21982407f79b51375687f41aca85ee34433229d8faa8e060a19ce0`로 고정했고 GREEN·RED 사전 검토 후 Root가 단일 guard를 실행했다. 공유 Graphify 재구축 없이 소유 코드/시험/검산 AST만 갱신했다.

## 중단과 보존된 범위

parent 실행 상태는 `rss_limit`, 종료코드−15다. guard 경과 84.951초, 표본 최대RSS 1,074,937,856bytes는1,073,741,824bytes 한도를1,196,032bytes 넘었다.0.25초 간격 표본이며 OS 강제 할당 상한은 아니다. 시간 한도(내부600초/외부660초) 중단이 아니다.

실제 row시작26회·완료25회, HVP시작/완료2/2, 12차원 풀이시작/완료1/1, 후보9개·확정1개다. 첫점 row24개는 완료했고 다음점에서 row0 하나 완료·row1 시작 기록이 남았다. 두 번째 HVP·풀이·스텝은 없다. 예정72row/6HVP/3풀이/3확정을 달성한 것으로 계산하지 않는다.

child 원본은 `phase=running`이며 source_after와 전역 input_before/after/runtime_before/after 객체가 기록되지 않았다. **전체 실행의 terminal closure나 source_unchanged를 주장하지 않는다.** 고정 plan pins와 source_before는 현재 파일과 일치했고, 저장 첫 스텝의 승인 flags/P2/제어 hash가 닫힌다. 첫 확정점 이후의 불완전 row 작업을 새 optimizer 결과로 승격하지 않았다. 원시 JSON과 무손실 gzip·run/resource는 실제 상태 그대로 보존했다.

## 메모리 조사와 다음 작업

정적 조사에서102.8MB의 pretty JSON checkpoint가 row 시작/완료마다 통째로 직렬화되고, 이전 확정 iteration과 동일한 비교 진행 기록이 중복 저장됨을 확인했다. 주요 serialized 부분은 iterations약61.46MB·comparison_progress약29.37MB다. 활성 VJP pullback과 이 직렬화가 겹칠 수 있지만 저장 자료만으로 특정 할당 하나를 RSS 초과 원인으로 확정하지 않는다. 이전점의 AD graph가 누수됐다는 증거도 얻지 않았다.

다음 별도 계획의 직접 후보는 atomic writer를 streaming JSON으로 바꾸고, 확정 iteration 저장 후 중복된 이전 comparison_progress를 비우는 것이다. 수학과 보존 의미·원자적 확정·동일한 자원 한도를 유지해야 한다. 이는 제안이며 이번 frozen producer에 적용하거나 새로운 production 실행으로 효과를 검증하지 않았다. 먼저 이 transient 기록 비용을 다룬 뒤 새 확정점에서 현재 rows/HVP를 갱신해 GN 반복을 이어갈 수 있다.

기존 1차 역사적8/8=100%, 현재 외부 FV 가중70/100은 유지한다. 적격 최적점·접선 곡률·양측 법선 최소·활성 안정성·수반/VJP·재분석·독립 합성 미래검증은 미완료다. θ는 최적화 보조변수, Q=0은 모델 활성면이며 잔차 감소는3시간 예측오차 개선율이 아니다.
