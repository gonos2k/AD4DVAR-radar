## 수정 검토에서 함께 차단한 실수

T1 회귀의 pytest.approx 기본 absolute tolerance는 1e-200과 0을 같게 볼 수 있다. abs=0 및 양수 검사를 사용해 실제 이전 결함을 구분했다.

초기 수정 후보의 전체 행렬 최대값 기반 대칭화는 diag(1e308,-1e-16)의 작은 음의 고윳값을 0으로 만들었다. 최종 구현은 서로 전치인 성분 쌍마다 척도를 정해 평균한다. 양·음의 작은 고윳값과 최소 subnormal 대각값을 보존하는 시험을 추가했다. 이는 수정 후보에서 발견해 최종 반영 전에 차단한 결함이며, PR239 원본 결함과 구분한다.

대칭화나 norm 산술을 안정화하는 것은 목적함수·제어 계량·gradient·rank 기준·정상성 허용오차의 변경이 아니다. 유한하게 표현되는 값을 불필요하게 거부했던 시험도 고쳤고, 실제 표현할 수 없는 norm·좌표 정규화·고윳값은 계속 거부한다. 반환하는 Hessian 비대칭 허용오차의 이름은 relative_tolerance로 단위를 명시한다.

## 기존 실행 기록의 독립 대조

끝점 진단은 과정 실행 completed / 수치 diagnostic_refusal이다. 원래 J=0.08389718093130327, Phi=1.7635966239794696, 최대 gradient=1.0588168237438937 및 엄격한 3600단계 분기가 재현됐다. 실행 243.165초, 표본 RSS 369,295,360 bytes, 종료코드 0이며 외부 자원 종료·monitor 오류가 없다. 새 Hessian과 완료 HVP 횟수는 미기록이다. 내부 deadline은 연산 경계에서 검사하고, 종료 기록 시간까지 포함하면 240.948초다. 300초 외부 wall 안에 있으며 이를 hard 240초 제한으로 주장하지 않는다.

미확보 곡률을 이전 계산점의 Hessian으로 대체하지 않는다. 이번 helper·가드 수리를 실제 3시간 곡률·정상점·응답 확보로 계산하지 않는다. 활성면 안정 근방·유한 영향·독립 기상예측/학습/불확실성·최신 전체 Linux 통과·과거 GRAPH_REPORT 원문 복구는 기존 미완료로 유지한다.

## 최종 검증 범위

- 집중 시험: 81 passed, 기존 경고 18개. 수학 진단 28건·가드 18건·끝점 계약/연결 35건의 한 pytest 실행이며 과거 32/62건과 누적하지 않는다.
- 여섯 파일 오류 수준 basedpyright: 0 errors / 0 warnings / 0 notes.
- 취소 검증은 작은 Python 자식에 실제 SIGTERM을 보낸 시험이다. 자식 process group 종료·회수, resource 기록, 이전 signal handler 복원을 확인했다. FV 자식을 실행한 것은 아니다.
- 기존 로그·report·dangling symlink·고정 .tmp symlink·서로 충돌하는 출력 이름은 파일 또는 mock guard 시험으로 확인했다.
- 취소/monitor 실패는 execution failed, wall/RSS 제한은 resource_limited로 분류한다. 저장된 자식 numerical_status와 분리한다. guard 오류는 실행 실패 기록 후 예외를 그대로 전달한다.
- 부모는 자식 c/p vector·hash·입력·소스 map·runtime을 원본 및 부모 전후 기록과 직접 대조한다. public guard의 유한 양수 wall / 양의 정수 RSS 계약도 시작 전에 검사한다.
- Graphify: 기존 구조 참조 후 여섯 파일 격리 갱신, 124 nodes / 373 edges. 공유 graph/report 불변.

앞으로 끝점 진단은 저장소 root에서 .venv/bin/python -m examples.weather_scenarios.fv_point_3h_endpoint_diagnostics --guarded ... 경로를 사용한다. 이 감사에서는 실제 FV 진단을 다시 실행하지 않았다. bare child 모드는 호환성을 위해 유지하며 별도의 외부 가드가 필요하다. 보존한 과거 runner·역사적 script의 SIGTERM 안전성까지 수리한 것으로 주장하지 않는다. 다른 legacy 호출부의 새 가드 채택은 별도 미검증 범위다.

변경 후 과거 manifest의 code SHA가 현재와 달라지는 것은 정상이다. 당시 코드와 결과의 연결은 Git 원본과 과거 기록으로 유지하고, 이번 수리의 소스·시험·검토·AST는 별도 manifest에 저장한다. 새 곡률, 3시간 정상점·응답, 활성면 전환의 유한 영향, 독립 기상 검증은 이번 공학·산술 보강으로 종료하지 않는다.


## 최종 통합 검토

SIGTERM을 무시하는 하위 프로세스가 대표 자식 종료 뒤 남는 경우를 실제 작은 프로세스 시험으로 추가 확인했다. 새 가드는 기존 helper가 직접 자식을 회수한 뒤 남은 동일 process group 구성원을 SIGKILL로 정리한다. 정리 여부·오류를 반환값과 저장 resource JSON에 동일하게 남기고, 예상 밖의 잔류 프로세스 정리가 필요했다면 정상 실행 완료로 승격하지 않는다. 별도 session으로 이탈하는 후손이나 전체 후손 RSS의 통합 감시까지 주장하지 않는다.

두 호출이 같은 실행 폴더에서 동시에 freshness 검사를 통과하는 반례는 배타적 .guarded-launch.lock으로 차단했다. marker는 preflight·spawn 전에 open('x')로 만들고 실패 이후에도 보존한다. barrier로 동기화한 두 caller 시험에서 기록·실행은 한 번만 일어났다. 이 시험은 가드를 대체한 파일 계약 시험이며 같은 프로세스의 동시 forward AD 검증이 아니다.

최종 GREEN·RED는 여섯 소스·시험 파일의 해시와 위 경계를 독립 검토해 GO를 주었다. 원래 수치 연산 소스 64개, 과거 실행 근거 15개, 구 runner 및 실행 script의 bytes는 불변이다. 새 manifest는 이번 수정·검토·재현·시험·격리 AST만 연결한다.
