# PR247 current Newton step: RED audit

Scope: `examples/weather_scenarios/fv_point_3h_current_newton_step.py` and `tests/test_fv_point_3h_current_newton_step.py`, with supporting calls in the bounded-step module. No code was changed and no new HVP was run.

## Finding: cached Hessian is not bound to the historical objective-source snapshot

**Severity: scientific-integrity gap for a regenerated plan; not an invalidation of the recorded attempt.** In `load_base` (target lines 28–63), the plan's source/archive hashes are checked against the present checkout, and it is required to mention every path in `base["source_before"]`. It never checks that the digests for the historical curvature/objective dependencies still equal `base["source_before"]`. `run` repeats the same plan-to-working-tree check at lines 105–109. As a result, a newly generated plan can bless a changed numerical objective implementation while retaining the old cached Hessian. The fresh base check at lines 129–140 compares branch/margins and endpoint J/Phi/gradient against the receipt, which cannot identify changes that vanish through first order at the base point.

Concrete supported mathematical counterexample: for base control `c0`, change an objective from `J(c)` to `J(c) + (lambda/2)||c-c0||^2`. At `c0`, J and its gradient are exactly unchanged and so can pass the fresh endpoint metrics and strict branch checks, while the Hessian changes by `lambda I`. A `.venv/bin/python` FP64 toy reproduction gave identical base J (`1.0`) and gradient (`[0.4, -0.2]`) for both objectives, but Hessians `diag(2,3)` versus `diag(9,10)` for `lambda=7` (Hessian difference norm `9.89949`). The candidate then uses the original cached H to define its Newton direction even though the present objective has a different curvature.

Suggested narrow repair: require the plan's digest to match `base["source_before"]` for the historical objective/Hessian dependencies (or pin and check an explicit dependency subset), while allowing the current caller and its test to have newer plan pins where they were not part of curvature construction. Add a regression with the quadratic perturbation above so equal base J/g cannot stand in for Hessian-source identity.

Current archived attempt is unaffected: the plan SHA is `d7f639e82dcd9445eeef0e32472194b57f31088dc1247e22b52ab0acc37f4a8f`, and every path shared between the plan's source map and curvature `source_before` has the same digest. The run record shows a completed guarded execution, child exit 0, no termination/monitor error, and `phase=finished`, `fixed_input_unchanged=true`. This is a latent invalidation gap if the plan is refreshed after a relevant source change, not evidence that the archived output used changed sources.
