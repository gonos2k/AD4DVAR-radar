# 스트리밍 checkpoint와 부분 GN 재개 — 2026-10-10

GREEN·RED 팀 검토와 영향 시험을 거쳐 저장 경로를 수정했다. 수정된 계획의 실제 실행은 두 스텝을 확정한 뒤 RSS 한도로 중단했다. 세 단계 완주와 최종 최적점은 미완료다.

## 수정 및 검증

- 전체 JSON 문자열 생성 대신 `JSONEncoder.iterencode()`를 같은 디렉터리의 독점 임시 파일에 기록하고 성공한 뒤 `os.replace()`한다. 실패 시 이전 확정 파일을 유지하며 자신이 만든 임시 파일만 정리한다.
- 확정 저장에서 `comparison_progress`를 제외한 snapshot을 먼저 원자적으로 기록하고 성공한 뒤 메모리의 중복 진행 상태를 제거한다. 확정 이력·개별 gradient·분기 trace는 보존한다.
- PR #274의 닫힌 첫 확정점 `7cec4c62…41fb7dd`만 새 시작점으로 읽고 미완료 다음점의 row·풀이를 새 연산으로 승계하지 않는다.
- 첫 재개 시도는 입력 재자격에서 거부됐다. 제어 SHA만 갱신하면서 제어 의존 `shifted_flow_fractions`를 이전점 값으로 남긴 것이 원인이다. strict 검사는 유지하고 저장된 제어의 `tanh(c[20:25])`도 재구성했다. 실패 소스·계획·raw/gzip/run/resource/log는 보존했다. 총 guard 시작은 두 번(실패 preflight 한 번, 수정 계획 한 번)이다. 수정 실행은 `--output/--resource/--log`에 attempt2 경로를 명시했다. 이 모듈의 기존 기본 attempt1 경로로 재실행하면 보관 실패 기록을 침범하므로 사용하지 않는다. 실패 시 현재점 gradient·row·HVP·후보·확정은 없었으며 seed 준비가 없었다고 주장하지 않는다.
- 수정 계획 SHA `529110d25ca28ac85ab3ce3fa2fd23a8b2a8ba0122c2f184ab5e26a3c20b4f17`: 142 source / 168 archive pin을 확인했다.
- 수정 후 영향 시험 45개 통과, 기존 경고 18개, 46.66초. 4개 변경 코드·시험 파일 basedpyright 오류/경고/노트 0. 수정 전 103개 결과를 수정 후 검증으로 승계하지 않았다.
- 수학·배율·후보 탐색·승인 helper 여섯 개 AST는 변경 전과 같다. Graphify는 기존 구조를 참조하고 소유 파일만 격리 AST 갱신했다.

## 자원 및 미완료 근거

- 437.16104225초에서 guard `rss_limit`, exit −15. 표본 최대 RSS 1,091,633,152 bytes; 한도 1,073,741,824 bytes, 0.25초 표본. 운영체제 OOM이나 순간 최대 RSS를 인증하지 않는다.
- row 시작/완료 72/72, HVP 4/4, 풀이 시작/완료 counter 3/3. 앞의 두 점의 풀이 이력에 더해 세 번째 현재점의 top-level `dense_solve_audit`가 있다. 세 번째 row·풀이를 HVP까지 갖춘 적격 방향이나 확정점으로 세지 않는다. 세 번째 HVP·후보·확정은 없다. 저장된 row·동일 제어의 P2 gradient로 B를 다시 만든 상대오차는 1.18e−16, 풀이 vector 상대오차는 1.17e−13, 선형잔차는 1.40e−15로 budget 2.15e−12 안이다. S의 최소 고윳값은 1.00166이다. audit 자체에는 base SHA가 없으므로 현재/마지막 확정 f2ca 상태·theta·24 row 문맥으로 연결했다. 이는 국소 풀이 검산이며 전체 세 번째 GN 점의 완료가 아니다.
- raw는 `phase=running`. 전체 종료의 source_after 및 전역 input/runtime 전후 기록은 없다. 승인된 두 점의 근거와 전체 실행 종료 자격을 구분한다. PR #274의 누락된 종료 검증도 채워 넣지 않았다.
- 최종 원시 checkpoint 172,541,692 bytes, lossless gzip 1,244,993 bytes. 현재 raw에 `comparison_progress`가 없는 것은 두 번째 확정 이력이 원자적으로 저장된 뒤 중복 필드를 제거했고, 세 번째 점이 아직 HVP·direction-progress 단계에 이르지 못한 상태와 일치한다. 확정/쓰기 실패 수명주기는 focused regression이 직접 확인한다. 이 raw 상태만으로는 전체 Python/Tensor 메모리 절감을 정량 인증하지 않는다.
- 약 4.91MB 합성 writer 시험에서 출력 바이트·SHA가 같았고 쓰기 구간 Python 추적 peak는 31,667,559 → 64,827 bytes였다. 생산용 RSS·Tensor 그래프·속도 향상 측정은 아니다.

PR #274보다 다음 계산점까지 더 진행했지만 시작점·누적 이력·작업량이 다르므로 RSS 차이를 저장 변경의 순수 효과나 일반적인 가속률로 계산하지 않는다. 전체 이력의 반복 저장 비용과 미분 작업의 활성 메모리는 여전히 검토 대상이다. 추가 실제 guard는 실행하지 않았다.
