실제 집계는 row 역미분 67회(24+24+19), GN 풀이 2회, HVP 4회, slot 및 실제 후보 평가 각각 36회(17+19), P2 확정 2회다. 마지막 점의 row 19개는 미완료 준비이며, 그 점의 GN 풀이·HVP·후보·확정은 0회다. 과거점의 미분을 새점 연산으로 승계하지 않았다.

## 이번 보강과 검증

PR289의 차트 생성 전 평가 시작 횟수 증가를 새 후속 경로에서 해결했다. 기존 frozen producer·계획·진단·확정 기록은 변경하지 않았다. PR286의 검색 기록 helper를 새 producer에서 사용해 slot 시작/완료와 실제 평가 시작/완료를 구분한다. 실제 정상 검색에서도 두 수가 따로 저장됐다. 차트 실패·영 이동·비유한 이동·반경 거부·평가 timeout은 합성시험에서 확인했다.

사전 GREEN/RED에서 발견한 두 후속 결함도 실제 실행 전에 보강했다. 부모 선택 후보의 전체 G를 제어·theta·R에 결합해 보관하고 매 계산점에서 성분별 재현을 검사한다. 비유한 반환 후보 facts는 수치값을 JSON null로 기록하고 finite/Armijo gate를 거부한다. 정상 후보의 원래 수치·목적함수·gradient는 바꾸지 않는다. JSON 거부와 다음 후보 진행의 합성시험은 생산용 비유한 FV 전체를 재실행한 인증이 아니다.

영향 시험 18개 통과(2.20초), 타입 오류·경고 0개, 격리 Graphify AST 33노드·115엣지(모델 토큰 0), 소스 173개·보관 파일 248개 핀과 정확 snapshot, raw/gzip/run/resource 해시·무손실 압축을 확인했다. GREEN/RED는 저장 근거와 합성시험만 검토했다. ROOT의 실제 FV guard와 합산해 여러 생산 실행으로 집계하지 않는다.

## 한계와 다음 기준점

P3 상태 표기: 최상위 `dense_solve_audit`는 두 번째 계산점(index 1, b9cea52e)의 마지막 완료된 풀이 기록으로 남는다. 세 번째 계산점(index 2, fec9f306)의 풀이가 아니다. 현재 연산 자격은 per-point 닫힌 이력·계산점 식별자·집계·readiness=false로 판정해야 한다. 다음 producer에서는 해당 최상위 기록을 점 식별자로 명시하거나 새점에서 제거하는 편이 정확하다. 이번 동결 결과에는 이 구분을 문서와 metrics에 명시했다.

실제 내부 예산 종료는 두 P2 이후 세 번째 row 계산 중의 prefix 보존을 확인했다. 후보 평가 도중 timeout이나 OS 강제 종료의 실제 검증은 아니다. 정확한 PR286 producer의 기존 bef459 시작 계획을 실행한 것도 아니다. 새 후속 producer가 같은 검색 helper를 사용한 실제 실행이다.

새 기준점 fec9f306의 row는 19/24까지만 준비됐다. 새점의 완성된 GN·HVP·방향이 없고, 적격 최적점·정확 곡률·수반·재분석·미래점수도 미완료다. 다음에는 현재점 연산의 자격과 실제 허용 이동을 확인해야 한다. 동일 selector 강제, 원래 잔차 투영, 다른 solver·prior·관측·limiter 변경으로 감소를 만들지 않았다.

기존 1차 이론 실증 100%, 현재 FV 확장 약 70%를 유지한다. 이번 수치 감소는 최적화 잔차에 관한 것이며 기상 상태 오차나 3시간 예측오차의 감소율이 아니다. 운영·배포·실자료는 분모에서 제외한다.
