# Same-point tangent preconditioner comparison — GREEN design review — 2026-10-09

## Disposition

The proposed projected Jacobi direction is mathematically admissible as a preconditioned tangent-gradient search direction if the diagonal is built from the exact production residuals, the common-face row check passes, and the denominator floor is fixed before the two-arm comparison. It is a search metric, not a Hessian solve or a positive-curvature certificate. I found one case-specific correction: the current 33cb point problem has **zero field-smoothness weight**, so its existing field Laplacian contribution is zero. Do not import the default `AnalysisConfig.field_smoothness_weight=0.01` into this comparison.

This is a design-only review. I did not compute observation rows or HVPs, run the FV model, tests, or guard, or edit source.

## Exact objective and units

`FVPointResearchProblem.objective` forms point-observation residuals only after the model trajectory is converted from echo to dBZ and sampled at fixed off-grid points. It applies quality and standard-deviation scaling, then the fixed observation whitener, then sums pseudo-Huber costs, and adds the control and field priors ([fv_point_research_problem.py](/Users/yhlee/ADVAR/src/advar/fv_point_research_problem.py:320)). The fixed case uses 12 observations (`3 × 4`), no missing mask, and a nontrivial 4×4 correlation matrix applied per frame ([fv_point_research_problem.py](/Users/yhlee/ADVAR/src/advar/fv_point_research_problem.py:69), [fv_point_response_preflight.py](/Users/yhlee/ADVAR/examples/weather_scenarios/fv_point_response_preflight.py:75)). Therefore the 12 scalar rows must be the **already standardized and whitened** residual components from that exact path; do not use raw dBZ or pre-whitener residuals for either (A_pm) or the robust weights.

For the configured pseudo-Huber cost, `delta=2` in these dimensionless residual units ([variational.py](/Users/yhlee/ADVAR/src/advar/variational.py:150)); its scalar curvature is exactly

`ell''(r) = (delta / hypot(delta, r))**3`.

This is the positive outer-curvature factor for the robust Gauss-Newton term. It is not the existing IRLS weight, which has a different power. In these standardized-residual/control coordinates, `ell''` is dimensionless, each residual row gradient has inverse-control units, and the diagonal terms have objective curvature units per control squared. `W` has reciprocal-curvature units; the direction `-P W P g` remains a control-space direction. The preconditioner must not change the original scalar objective or its Armijo checks.

The point case has a plain quadratic control prior: `_control_prior_residual` returns the control when there is no neural-prior std/mask ([variational.py](/Users/yhlee/ADVAR/src/advar/variational.py:5476)); FV preparation also rejects neural priors. Controls are standardized in the unchanged objective `0.5||c||²`, so the original ambient prior curvature supplies a unit floor even where `diag(P I P)=1−nu_i²` approaches zero. Use `W_i=1/max(1, D_raw[i])` after rejecting nonfinite `D_raw`; this keeps `0 < W_i ≤ 1` and gives a proper reciprocal-curvature scale in the fixed control coordinates. Record which components hit this floor. The unit floor is a preconditioner choice from the existing prior, not a damping term added to the objective.

The field-smoothness term vanishes for this case. The seed constructs `AnalysisConfig(field_smoothness_weight=0.0)` ([fv_minmod_inverse_probe.py](/Users/yhlee/ADVAR/examples/weather_scenarios/fv_minmod_inverse_probe.py:118)), the long-horizon case carries that config into the nonzero-flow point case ([fv_long_horizon_case.py](/Users/yhlee/ADVAR/examples/weather_scenarios/fv_long_horizon_case.py:134)), and the point wrapper reuses that frozen state ([fv_point_3h_forward_case.py](/Users/yhlee/ADVAR/examples/weather_scenarios/fv_point_3h_forward_case.py:21)). Thus `L=0` for this fixed experiment. If the implementation remains generic, use the projected field term `diag(P L P)`; for symmetric (L), component (i) is `L_ii − 2 nu_i (L nu)_i + nu_i² (nuᵀ L nu)`. Using only unprojected `diag(L)` would be wrong for a nonzero smoothness prior.

## Projected diagonal and descent direction

At the fixed base `33cb86ca73a404e6ff9260acbf63ee97f248ac0c1f529427eb1af1ec85a43586`, keep the objective, parameters, observations, boundaries, time, selected face, and theta fixed. Let `n=grad Q`, `nu=n/||n||`, `P=I−nu nuᵀ`, `g_mix=(1−theta)g_minus+theta g_plus`, and `t=P g_mix`. The preconditioned proposal is `d_spd=−P W t`; the control baseline is `d_base=−t`. With positive finite diagonal `W`, `P W P` is positive definite on the tangent space. Because the current side-gradient jump is required to be normal to the face, both one-sided objective slopes equal `tᵀd`; for the preconditioned direction this is `−tᵀW t < 0` when `t≠0`. Retain the existing finite, resolved-normal, both-side descent, and `FᵀDF<0` gates to catch roundoff or any violated common-face premise.

For side (s∈{-,+}), define each row `a_s,k = grad_c r_s,k` from the 12 whitened residual components and its saved residual value `r_s,k`. The projected robust-GN diagonal is

`D_data[i] = (1−theta) sum_k ell''(r_-,k) * (P a_-,k)[i]**2 + theta sum_k ell''(r_+,k) * (P a_+,k)[i]**2`.

The SPI/common-face qualification should compare `P a_-,k` and `P a_+,k` row by row using an FP64 roundoff budget scaled to the row and projection norms. Also require the two side residual vectors and their reconstructed data costs to match on the current face within contract-scale tolerances. Since whitening mixes the four observations at each time, the comparison is on the whitened rows, not the unwhitened point rows.

The selected face is `Q(c)=sum_i w_i tanh(c_i)` on controls 20–24 ([face_transition_diagnostic.py](/Users/yhlee/ADVAR/examples/weather_scenarios/fv_point_3h_face_transition_diagnostic.py:83)). Its exact diagonal curvature is `q_i = -2*w_i*tanh(c_i)*(1−tanh(c_i)**2)`. For `mu=(nᵀg_mix)/(nᵀn)`, the constrained Lagrangian curvature contribution is `−mu * diag(P Q_cc P)`, where

`diag(P Q_cc P)[i] = q_i*(1−2*nu_i**2) + nu_i**2 * sum_j(nu_j**2*q_j)`.

The sign is negative because the constrained Lagrangian is `J − mu Q` under this multiplier convention. This term is an approximation to constrained curvature when combined with Gauss-Newton data curvature; it does not recover the omitted robust residual-second-derivative terms.

Build the raw diagonal as `D_raw = D_data + diag(P I P) + diag(P L P) − mu*diag(P Q_cc P)`; for this fixed case `diag(P L P)=0`. Since the Lagrangian term can make components negative, use the approved ambient-prior floor `W_i=1/max(1, D_raw[i])`. Reject nonfinite `D_raw` before the maximum and record the number of components floored at one, `D_raw`, and `W`. This floor leaves the original objective unchanged and makes the diagonal metric strictly positive and bounded by the fixed unit prior curvature.

## Face path, HVPs, and two-arm decision

Both directions are tangent at the common base. Generate candidates with the existing implicit face chart, using the current pivot and η=0, so `Q=0` holds on the finite path; check the actual curved control displacement against radius `0.05`, not just `alpha*||d||`. The chart Jacobian and pivot implementation are in [face_transition_diagnostic.py](/Users/yhlee/ADVAR/examples/weather_scenarios/fv_point_3h_face_transition_diagnostic.py:90), and existing alpha/search code already owns theta bounds, actual path radius, and the 16-candidate search cap ([tangent_continuation.py](/Users/yhlee/ADVAR/examples/weather_scenarios/fv_point_3h_tangent_continuation.py:194)). Keep `Q/0.84` scaling, fresh actual-J/F² Armijo tests, strict branch/face gates, and individual side-gradient final closure.

Each arm needs its own two fresh side HVPs at this same base and its own direction. Compute `delta_theta` from those products using the existing implicit normal equation, then its own `DF`; no PR267 or previous-step HVP/direction is reusable. The pair comparison therefore has four current HVP calls total. Preserve a direction/arm identifier or direction hash in the HVP records: both arms share base hash and theta, so grouping only by base/side cannot distinguish the two `−/+` pairs. The existing one-direction runner's “two HVPs per base” receipt check also needs an explicit paired-comparison variant.

Run each search arm independently with the same alpha policy and no more than 16 candidates per arm. Among only candidates that pass all actual J/F² and current-pair checks, select the smallest actual endpoint `F²`; apply a predeclared dtype-scaled tie rule with actual J as the next key and the baseline as the deterministic final tie-break. Store both arm directions, D/floor, HVP pairs, model predictions, candidate counts, and actual endpoint receipts. Only the selected candidate is committed and gets the independent fresh final repeat. If either arm or the row-model calculation fails, do not commit a partial comparison; preserve the same base point. This is a same-base directional comparison, not an inherited step from the three-step resume.

## Cost, claims, and pre-implementation checks

The row model requires 24 reverse-mode scalar residual gradients (12 per side), distinct from the four directional HVPs. Avoid materializing a full 26×26 Hessian or retaining 24 reverse graphs; collect finite row vectors in bounded memory. At most 16 candidate evaluations per arm implies up to 32 candidate slots, plus base observation/closure and one selected final repeat. The prior three-step run used about 79.3 seconds and sampled 565 MB, but this added Jacobian and dual-search work is not established by that runtime. The proposed one-guard budget of 600 seconds internal, 660 seconds external, and sampled 1 GiB is appropriately explicit; enforce internal deadline checks during row construction and between candidates, and report RSS as sampled rather than hard OS memory enforcement.

Before any guarded launch, tests should verify: production-cost reconstruction from the exact whitened 12-vector; side residual equality and `P A_-≈P A_+`; the face-curvature diagonal against a small dense `P Q_cc P`; the identity-prior projection; `diag(P L P)` (including its zero result for this fixed case); positive finite `W≤1` for zero/negative/large diagonals; both directions' tangent/descent identities; each arm's fresh-HVP association; and deterministic winner/tie behavior. `W=I` exactly reproduces the baseline direction. Do not assume general scale invariance for `W=cI`: the normal theta correction includes the fixed normal component of `g_mix`, so rescaling `d` does not generally rescale `delta_theta`, and the alpha cap at one can also change the endpoint. These checks establish the model and implementation contract; they do not certify the true projected Hessian as positive or establish a minimum.
